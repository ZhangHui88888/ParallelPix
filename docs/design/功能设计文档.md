# 功能设计文档

> 本文按实现职责划分模块，说明功能如何被使用和运转；不维护接口参数、请求响应结构或数据库字段定义。

## 系统定位

ParallelPix 是本机运行的商品图片并行处理与性能实验工具。学生通过 CLI 或 Streamlit 仪表板配置实验，系统使用 Sequential、OpenMP 或 CUDA 后端完成相同的图片标准化流程，验证输出正确性并保存性能结果；基础闭环后可使用 M8 Hybrid 同时调度 OpenMP 与 CUDA。

## 模块总览

| 模块 | 职责 | 覆盖需求 |
|------|------|----------|
| M1 本地性能仪表板 UI | 接收实验配置、启动 CLI、展示运行状态并读取 CSV 绘制结果 | FR-011 |
| M2 CLI Controller 与任务编排 | 解析和校验参数，选择后端并编排 M3～M8 | FR-001、FR-012 |
| M3 图片数据 I/O | 校验路径、扫描排序图片、加载水印并管理输出文件 | FR-002 |
| M4 公共处理模型与 Sequential | 定义统一图片模型、处理语义并提供单线程正确性基线 | FR-003、FR-004 |
| M5 OpenMP 后端 | 使用可配置线程数执行多核 CPU 并行处理 | FR-005 |
| M6 CUDA 后端 | 执行 GPU 像素并行、批处理、显存复用及分阶段计时 | FR-006、FR-010 |
| M7 验证与 Benchmark | 校验输出、执行预热与重复测量、汇总并写入 CSV | FR-007～FR-009 |
| M8 CPU-GPU Hybrid | 将图片拆分给 OpenMP 与 CUDA 并发处理，合并输出并比较纯后端 | 扩展实验 |

异常处理、日志和降级是贯穿各模块的横切规则，不再作为独立业务模块。

## M1 本地性能仪表板 UI

- 仪表板仅服务于本机演示，提供受支持的目录、后端、线程数和批大小选择。
- 提交后通过 M2 启动已编译的 Benchmark CLI，实时显示命令输出和成功或失败状态。
- 成功结束后读取 CLI 生成的 CSV，展示运行耗时、吞吐量、加速比及 CUDA 的 H2D、Kernel、D2H 分阶段时间。
- 仪表板不改写性能数据，也不计入 Benchmark 的计时范围。
- M1 只负责展示和交互，不承担参数业务规则、图片处理或性能指标计算。

## M2 CLI Controller 与任务编排

- 接收 M1 或终端提供的输入目录、输出目录、处理后端、线程数、CUDA 批大小及 Benchmark 参数。
- 校验参数完整性和组合合法性，将有效配置转换为内部任务对象。
- 按顺序调用 M3 加载数据、调用 M4/M5/M6 或可选 M8 中选定的处理后端，并调用 M7 完成验证与性能记录。
- 输出机器可判断的退出码和适合 M1 展示的进度、错误及结果路径。
- M2 只控制流程，不实现文件解码、像素算法、性能统计或页面展示。

```text
M1 或终端
  → M2 参数校验与任务编排
  → M3 图片数据 I/O
  → M4 / M5 / M6 / M8 处理后端
  → M7 验证与 Benchmark
  → 退出码、日志与 CSV 路径
```

## M3 图片数据 I/O

1. 校验输入目录存在且可读取、输出目录可创建或写入，并校验水印文件可解码。
2. 扫描输入目录中的受支持图片，按稳定顺序排序；逐个解码并报告损坏或不支持的文件。
3. 为每项有效输入建立处理任务；无有效图片时不启动后端计算。
4. 将标准化结果写入输出目录，输出尺寸统一为 1024×1024；写入失败时保留错误原因并标记任务失败。

## M4 公共处理模型与 Sequential

### 统一处理语义

每张图片按固定顺序执行中心裁剪、双线性缩放、亮度调整（系数 1.10）和右下角半透明水印叠加（透明度 0.35）。三个独立后端和 Hybrid 子任务必须使用同一配置和处理顺序。

### Sequential 基线

- 单个 CPU 线程按任务顺序处理图片和像素。
- 不调用 OpenMP，也不使用 OpenCV 的现成图像处理算法。
- 输出作为 OpenMP 与 CUDA 的正确性参考和性能基线。

## M5 OpenMP 后端

- 在不改变处理语义的前提下，对图片任务或输出行进行并行处理。
- 支持用户配置线程数，并可运行 1、2、4、8 和设备支持的最大线程数实验。

## M6 CUDA 后端

- 按输出像素并行执行处理，支持可配置批大小。
- 批量传输数据并复用显存缓冲；记录 H2D、Kernel 和 D2H 的独立耗时。
- 每次 CUDA 调用均检查错误状态。

## M7 验证与 Benchmark

### 输出验证

1. 先以 Sequential 后端生成对应基准输出。
2. 比较 OpenMP 和 Sequential 的输出尺寸与像素值，要求完全一致。
3. 比较 CUDA 和 Sequential 的输出尺寸与像素值，要求每通道最大绝对误差不超过 1。
4. 比较 Hybrid 合并输出的数量、顺序、来源路径和像素值，整批每通道最大绝对误差不超过 1。
5. 验证失败的运行标记为无效，不用于计算或展示加速比。

### 性能测试与报告

- 每组实验先预热 2 次，再正式执行至少 5 次。
- 汇总中位数、最小值、最大值和标准差，并计算吞吐量、加速比与并行效率。
- 将有效运行写入 CSV，至少包含后端、测试规模、耗时、吞吐量、加速比、并行效率和验证结果。

## M8 CPU-GPU Hybrid

- 仅在 M5 OpenMP 与 M6 CUDA 都可用时启用。
- 按配置比例把不同图片分给 CPU 与 GPU，两个分支同时运行，不重复处理同一张图片。
- 保留原始图片索引，完成后按输入顺序合并，再由 M7 对整批输出执行 Sequential 对照验证。
- 完成后的静态轨迹区分 Hybrid CPU、Hybrid GPU 和总体完成进度；最终结论比较纯 OpenMP、纯 CUDA 和 Hybrid。
- 混合模式不保证更快；若内存带宽竞争和调度开销抵消收益，系统必须保留并展示真实结果。

## 横切规则：异常与降级

| 场景 | 系统行为 | 用户可执行操作 |
|------|----------|----------------|
| 参数或路径无效 | CLI 不启动任务，说明具体参数或路径问题并返回非零状态 | 修正参数或权限后重试 |
| 图片或水印不可读取 | 报告具体文件；没有有效输入时结束任务 | 替换或移除异常文件 |
| 无 CUDA 设备或驱动不可用 | 说明 CUDA 后端不可用，但 Sequential 与 OpenMP 保持可运行 | 选择 CPU 后端或配置 CUDA 环境 |
| CUDA 显存不足 | 自动缩小批大小重试一次；仍失败则报告失败原因 | 降低批大小或改用 CPU 后端 |
| 输出验证失败 | 标记本次运行无效，不写入有效性能结论 | 检查后端实现与运行配置 |

## 权限与可见范围

本项目为本机课程工具，不提供账号、角色或远程访问。运行者只能读取其具有读取权限的本地输入和水印文件，并向具有写入权限的输出目录及 CSV 位置写入结果。
