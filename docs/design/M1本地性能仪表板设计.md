# M1 本地性能仪表板设计

## 目标与边界

M1 是仅在本机运行的英文 Streamlit 单页控制台。它负责收集 Benchmark 配置、调用 M2 CLI、展示进程日志，并只读展示 M7 写入的 CSV。

M1 不读取或处理原始图片，不计算吞吐量、加速比或并行效率，不修改真实 Benchmark CSV，也不承担后台任务队列、远程访问和多用户并发。

## 页面结构

- 侧栏：运行模式、CLI 与数据路径、后端矩阵、图片数量、OpenMP 线程数、CUDA 批大小和重复次数。
- 状态区：展示 `idle`、`validating`、`running`、`success`、`partial` 或 `failed`，最多保留 500 行日志。
- 指标区：直接选择 CSV 已提供的最佳加速比、峰值吞吐量、最快计算时间，并显示通过验证的配置数量。
- 结果区：包含 `Overview`、`Scalability`、`CUDA Timing` 和 `Raw Data` 四个标签页。
- 历史区：按 `run_id` 和 UTC 时间选择运行记录，默认显示最新一次。

Demo 模式始终显示“Demo data — not measured”，只读取仓库内的虚构样例数据，不启动 CLI。

## 运行流程

```text
用户配置
  → M1 基础表单校验
  → DemoRunner 或 SubprocessRunner
  → 退出码与日志
  → 只读加载 CSV
  → Schema 校验
  → 按 run_id 展示有效结果
```

- 选择 OpenMP 或 CUDA 时，M1 自动将 Sequential 加入请求作为基线。
- Subprocess Runner 使用参数数组和 `shell=False`，不接受整段 Shell 命令。
- CLI 退出码 `0` 为成功，`2` 为部分成功，其他值为失败。
- 成功或部分成功后必须存在结果 CSV，并出现新的 `run_id`，否则本次运行按失败处理。
- `validation_passed=false` 的行保留在原始表格中，但不进入性能图表。

## M2 命令契约

```text
parallelpix benchmark
  --input <dir> --output <dir> --watermark <file>
  --backends sequential,openmp,cuda
  --image-counts 10,50,100
  --threads 1,2,4,8
  --cuda-batches 1,4,8
  --warmups 2 --repetitions 5
  --csv <file> --append
```

## CSV 契约

每行表示一个已经由 M7 聚合的实验配置。`compute_ms` 和 `end_to_end_ms` 为中位数；不适用字段保持为空。

```text
run_id, recorded_at_utc, backend, thread_count, cuda_batch_size,
image_count, input_resolution, output_resolution, warmups, repetitions,
compute_ms, compute_min_ms, compute_max_ms, compute_stddev_ms,
end_to_end_ms, end_to_end_min_ms, end_to_end_max_ms, end_to_end_stddev_ms,
images_per_second, megapixels_per_second, speedup, parallel_efficiency,
validation_passed, max_pixel_error, h2d_ms, kernel_ms, d2h_ms
```

缺少必需字段、时间戳无效、验证字段无法解析或 CSV 为空时，M1 禁止绘图并显示具体错误。
