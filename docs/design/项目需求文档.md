# 项目需求文档

> 本项目需求以《技术架构文档》为事实来源，用于并行计算课程期末考试的开发、演示和验收。

## 业务背景

ParallelPix 是一个以跨境电商商品图片标准化为业务场景的并行计算课程项目。项目需要对同一批商品图片执行相同处理，并对比单线程 CPU、OpenMP 多核 CPU 与 CUDA GPU 三种计算方式的正确性和性能差异。

项目重点是证明并行计算在批量图片像素处理任务中的效果，说明数据规模、CPU 线程数、CUDA 批大小和 GPU 数据传输对性能的影响；不以建设真实电商业务系统为目标。

## 项目目标

| 目标 | 成功标准 | 状态 |
|------|----------|------|
| 提供统一图片处理能力 | 三种后端对同一输入执行一致的标准化处理 | 已确认 |
| 对比并行计算效果 | 输出可复现的执行时间、加速比、吞吐量和并行效率数据 | 已确认 |
| 保证结果正确 | OpenMP 与顺序结果完全一致；CUDA 单通道误差不超过 1 | 已确认 |
| 支持课程验收 | 可在 15～20 分钟内完成架构、Demo、代码和性能结论展示 | 已确认 |

## 目标用户

| 角色 | 说明 | 核心诉求 |
|------|------|----------|
| 学生/开发者 | 配置并运行三种后端，收集实验数据并完成答辩 | 快速运行、结果可信、数据可解释 |
| 课程教师/评审 | 审核并行设计、正确性、实验方法和性能结论 | 组件符合要求、比较公平、证据完整 |

## 范围与边界

### 本期范围

- 从本地目录批量读取、排序、解码和校验图片及水印。
- 执行中心裁剪、双线性缩放、亮度调整和右下角半透明水印。
- 通过统一 CLI 选择 Sequential、OpenMP 或 CUDA 后端，并配置路径、线程数和批大小。
- 输出统一规格图片，并验证三类后端的输出正确性。
- 执行预热、重复测量和性能统计，生成 CSV 与图表所需数据。
- 提供仅在本机运行的 Streamlit 性能仪表板，用于启动 Benchmark、查看命令输出和浏览 CSV 图表。
- 覆盖不同图片数量、分辨率、OpenMP 线程数和 CUDA 批大小的实验。

### 非本期范围

- 对外 Web 前端、后端 API、数据库和电商交易功能；本地 Streamlit 仪表板属于本期范围，但不提供远程访问能力。
- AI 图像识别/生成、外部云服务和真实用户数据管理。
- Spark、Kafka、Hadoop 等分布式计算组件。
- 使用 OpenCV 现成图片处理算法替代课程要求的像素级实现。

## 核心业务流程

1. 学生可通过本地仪表板或 CLI 指定输入目录、输出目录、后端及可选线程数或 CUDA 批大小；仪表板将选择转换为 CLI 命令执行。
2. 系统扫描并校验输入图片，加载水印，构建统一图片批次和处理配置。
3. 选定后端执行裁剪、缩放、亮度调整与水印叠加，生成标准化图片。
4. 系统以 Sequential 输出为参考，校验 OpenMP/CUDA 输出的尺寸和像素误差。
5. Benchmark Runner 对有效运行执行预热与重复测量，输出 CSV 指标。
6. 本地仪表板显示命令状态与输出，并在命令结束后读取 CSV，以表格和交互式图表展示性能结果。

## 功能需求

| 编号 | 需求描述 | 验收标准 | 状态 |
|------|----------|----------|------|
| FR-001 | 支持选择处理后端、输入/输出路径、OpenMP 线程数和 CUDA 批大小 | 非法参数给出明确错误并以非零状态退出 | 已确认 |
| FR-002 | 扫描、排序、解码和校验本地图片及水印 | 损坏图片、无效目录或无写权限可被识别并报告 | 已确认 |
| FR-003 | 对每张图片按固定流程完成中心裁剪、双线性缩放、亮度调整和水印叠加 | 默认输出为 1024×1024；亮度系数 1.10；水印透明度 0.35 | 已确认 |
| FR-004 | 提供单线程 CPU 后端作为正确性参考和性能基线 | 仅使用一个 CPU 线程，且不调用 OpenMP 或 OpenCV 现成处理算法 | 已确认 |
| FR-005 | 使用 OpenMP 对图片或输出行并行处理，并可配置线程数 | 可测试 1、2、4、8 及设备支持的最大线程数 | 已确认 |
| FR-006 | 使用 CUDA 对输出像素并行处理，支持批量传输和显存缓冲复用 | 可配置批大小，记录 H2D、Kernel、D2H 时间并检查 CUDA 错误 | 已确认 |
| FR-007 | 对比三类后端的输出尺寸与像素误差 | OpenMP 与顺序输出完全一致；CUDA 每通道最大绝对误差 ≤ 1 | 已确认 |
| FR-008 | 执行预热、重复运行和性能指标计算 | 每组预热 2 次、正式至少运行 5 次，并保留中位数、最小值、最大值和标准差 | 已确认 |
| FR-009 | 将有效运行结果写入 CSV，供图表生成与答辩使用 | 至少包含后端、规模、耗时、吞吐量、加速比、并行效率和验证结果 | 已确认 |
| FR-010 | 在无 CUDA 设备或显存不足等场景提供可解释的处理结果 | 无 CUDA 时 CPU 后端仍可运行；显存不足时自动缩小批大小重试一次 | 已确认 |
| FR-011 | 通过 Streamlit 启动已编译的 Benchmark CLI，显示运行状态并读取 CSV 展示性能图表 | 可选择受支持的测试参数；可看到命令输出、成功或失败状态；完成后展示耗时、加速比、吞吐量和 CUDA 分阶段时间 | 已确认 |

## 非功能需求

| 类型 | 要求 | 验收标准 | 状态 |
|------|------|----------|------|
| 正确性 | 三种后端执行相同处理语义 | 无效验证结果不得用于发布加速比 | 已确认 |
| 可比性 | 三类后端共享加载、配置、验证、计时和报告流程 | 测试条件一致，Sequential 作为基线 | 已确认 |
| 可复现性 | 记录运行配置、硬件与工具链版本 | CSV 包含实验配置；测试记录包含 CPU、GPU、内存和版本信息 | 已确认 |
| 性能测量 | 区分纯计算时间与端到端时间 | CPU 使用 `steady_clock`，CUDA Kernel 使用 CUDA Event | 已确认 |
| 可移植性 | CUDA 不可用时仍支持 CPU 后端 | 无 NVIDIA GPU 的设备可完成 Sequential/OpenMP 实验 | 已确认 |
| 可演示性 | 项目可在有限答辩时间内说明完整闭环 | 15～20 分钟内完成架构、Demo、代码和结论展示 | 已确认 |
| 本地化与隔离 | 仪表板仅服务于本机演示，不参与被测路径 | CLI 可脱离仪表板运行；仪表板不修改 CSV 指标、不计入性能时间 | 已确认 |
