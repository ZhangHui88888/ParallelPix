# M3 图片数据 I/O 设计

## 目标与边界

M3 负责把本地文件系统中的图片转换为后端共享的内存数据，并把后端产生的图片保存为无损 PNG。它覆盖目录扫描、稳定排序、图片与水印解码、批次补足、输出目录校验和 PNG 写出。

M3 不实现裁剪、缩放、亮度调整、水印混合、性能测量、CSV、输出文件命名或 Pipeline 编排。M7 已通过 M3 公开接口完成真实目录扫描、解码和 PNG 写出；这些编排职责仍不进入 M3。

## 数据流

```text
输入目录
  → 非递归扫描 JPG/JPEG/PNG
  → UTF-8 文件名稳定排序
  → 逐项解码并跳过坏图
  → 补足请求的有效图片数量
  → 连续三通道 BGR Image Batch

水印文件
  → 保留原始 Alpha 解码
  → BGR 颜色图 + 单通道 Alpha

后端输出 Image
  → 校验内存不变量
  → 校验或创建输出目录
  → PNG 内存编码
  → 临时文件写入并置换目标文件
```

## 公共数据模型

`Image` 是 M3～M6 的最小共享模型：

```text
Image {
  width, height,
  channels = 3,
  stride = width * 3,
  source_path,
  owned BGR pixels
}
```

像素必须为连续、紧密排列的 8 位 BGR 数据，`pixels.size()` 必须等于 `stride * height`。公共头文件不暴露 `cv::Mat`。

`Watermark` 包含一张符合上述约束的 BGR 颜色图，以及长度为 `width * height` 的 Alpha 平面。单通道和三通道水印的 Alpha 统一为 255；四通道水印保留解码后的 Alpha。最终透明度与全局 0.35 系数的组合属于 M4 处理语义。

## I/O 契约

### 目录扫描

- 只扫描指定目录第一层，不递归进入子目录。
- 支持大小写不敏感的 `.jpg`、`.jpeg`、`.png`。
- 其他文件静默忽略。
- 候选文件按 UTF-8 文件名字节序稳定排序，同名时以完整路径打破平局。
- 目录缺失、路径不是目录、目录不可读或没有候选图片均返回结构化错误。

### 图片与水印解码

- 使用 `std::filesystem::path` 读取文件字节，再交给 OpenCV `imdecode`，保证 Windows 中文路径可用。
- 普通图片用 `IMREAD_COLOR` 规范化为 8 位三通道 BGR。
- 水印用 `IMREAD_UNCHANGED`，只接受 1、3、4 通道；空文件、损坏文件、非 8 位图片或其他通道数失败。
- `load_batch` 从稳定目录顺序开始加载，坏图降级为警告并继续向后补足。
- 有效图片少于请求数量时整批失败，不把缩小规模伪装成成功实验。

### 输出管理

- 输出目录不存在时创建，存在但不是目录时失败。
- 目录通过私有临时探针验证可写，探针只由 M3 创建和清理。
- `write_png` 只接受 `.png` 目标，不修改尺寸或像素。
- 调用者必须显式选择 `FailIfExists` 或 `ReplaceExisting`。
- PNG 先编码到内存并写入同目录临时文件，再移动到目标；替换策略只允许移除普通文件，绝不删除目录。

## 错误模型

所有公共操作返回结果对象和 `IoIssue` 列表。Issue 包含错误码、Warning/Error 严重级别、关联路径和 UTF-8 消息。M3 捕获 OpenCV 与文件系统异常；后续真实 Pipeline 负责把 M3 Issue 映射为 M2 的 `WorkflowIssue`、日志和退出码。
