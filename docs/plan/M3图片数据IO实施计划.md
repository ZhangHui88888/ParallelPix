# M3 图片数据 I/O 实施计划

## 目标

实现独立、可测试的 `parallelpix_io` C++17 模块，完成 FR-002；当时不提前实现 M4/M7，现已由 M7 通过公开接口接入真实 Benchmark。

## 实施任务

| 任务 | 交付物 | 验证 | 状态 |
|------|--------|------|------|
| OpenCV 依赖 | 固定 baseline 的 `vcpkg.json`，仅启用 JPEG/PNG | 全新构建目录配置 | 已完成 |
| 公共图片模型 | `Image`、`Watermark` 及内存不变量 | 模型单元测试 | 已完成 |
| 目录与批次 | 非递归扫描、稳定排序、坏图补足 | 目录与批次测试 | 已完成 |
| 图片与水印解码 | BGR 规范化、Alpha 保留、Unicode 路径 | PNG/JPEG/灰度/RGBA 测试 | 已完成 |
| 输出管理 | 目录探针、PNG 写出、冲突与替换策略 | PNG 往返与异常测试 | 已完成 |
| 文档与回归 | 设计、测试、架构、README 和索引 | CTest、pytest、diff check | 已完成 |

## 全局约束

- 公共接口不暴露 OpenCV 类型。
- OpenCV 只用于解码、编码和数据接入，不实现课程核心像素算法。
- 不清空输出目录，不自动命名输出文件，不写 Benchmark CSV。
- 坏图可跳过，但绝不缩小用户请求的实验规模。
- M4 只通过集成测试消费 M3；M7 完成完整 Benchmark 契约前不替换 `ControllerOnlyPipeline`。
