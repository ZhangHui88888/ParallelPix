## 模块边界

- M1 是操作和展示层，不实现图片处理或性能指标计算。
- M2 是 Application Controller，只校验请求并编排 M3～M8，不承载文件解码、像素算法或统计逻辑。
- M3 负责数据进入和输出；M4、M5、M6 负责独立计算后端；M8 只组合 M5/M6 并进行异构调度；M7 负责验证与实验数据。
- 参数错误、文件错误、CUDA 不可用和显存不足等异常由对应模块识别，统一经 M2 转换为日志和退出码。

## 实施顺序

1. 已完成 M1 可运行 UI、Demo Runner、真实 CLI 适配口、样例 CSV 和浏览器验收。
2. 已完成 M2、独立 M3 与严格边界的 M4；M3→M4→PNG 链路已由 C++ 集成测试验证。
3. 已完成 M7 的预热、测量、验证、统计、原子 CSV 和真实 Sequential Pipeline；M1 可读取真实结果。
4. 已跳过 M5 并完成 M6：条件 CUDA 构建、共享预检、融合 Kernel、显存回退、分阶段计时、真机正确性和性能实验均已闭环。
5. 完成 M5 OpenMP 后端并执行三后端最终回归与答辩流程验证。
6. 在不影响课程基础验收的前提下实施 M8：扩展 Hybrid 矩阵和 CSV Schema，完成 CPU/GPU 并发、完成后轨迹、正确性验证及纯 OpenMP/纯 CUDA/Hybrid 对照实验。
