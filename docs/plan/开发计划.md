# 开发计划

## 项目状态

需求与总体架构已经确认。M1～M7 功能代码已经形成闭环：Sequential、OpenMP 和可选 CUDA 执行器均接入真实 Pipeline。M5/M6 测试代码已补齐；当前下一步是统一执行 CPU-only/CUDA-enabled 构建、全量回归、GPU 正确性、OOM 和性能实验。三后端闭环后再实施可选的 M8 CPU-GPU Hybrid 异构并行实验。

## 模块边界

- M1 是操作和展示层，不实现图片处理或性能指标计算。
- M2 是 Application Controller，只校验请求并编排 M3～M8，不承载文件解码、像素算法或统计逻辑。
- M3 负责数据进入和输出；M4、M5、M6 负责独立计算后端；M8 只组合 M5/M6 并进行异构调度；M7 负责验证与实验数据。
- 参数错误、文件错误、CUDA 不可用和显存不足等异常由对应模块识别，统一经 M2 转换为日志和退出码。

## 实施顺序

1. 已完成 M1 可运行 UI、Demo Runner、真实 CLI 适配口、样例 CSV 和浏览器验收。
2. 已完成 M2、独立 M3 与严格边界的 M4；M3→M4→PNG 链路已由 C++ 集成测试验证。
3. 已完成 M7 的预热、测量、验证、统计、原子 CSV 和真实 Sequential Pipeline；M1 可读取真实结果。
4. 已完成 M5/M6 代码、M7 注册、设备降级和待执行测试。
5. 统一执行 M1～M7 回归、CPU/GPU 正确性、OOM 和性能实验。
6. 回到 M1 完成真实 CLI 联调和最终答辩流程验证。
7. 在不影响课程基础验收的前提下实施 M8：扩展 Hybrid 矩阵和 CSV Schema，完成 CPU/GPU 并发、完成后轨迹、正确性验证及纯 OpenMP/纯 CUDA/Hybrid 对照实验。
